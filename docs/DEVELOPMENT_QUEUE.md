## Queue rules

- A blocked item stays in the queue with the blocker stated; do not work around missing secrets by committing credentials.
- A dependency may be reordered only after updating this queue and the relevant backlog entry with the reason.
- A blocked row may be skipped only for work that does not depend on it; record the reason on both rows.
- If a queued task is blocked by an unqueued prerequisite, insert that prerequisite ahead of it and document why.
- Do not mark work done based only on a successful build: include tests and the user-visible acceptance outcome.
- New work goes into `BACKLOG.md` first, then gets a queue row when prioritized. Keep task IDs stable so links remain valid.
